# 캐릭터 모델 크기·두께·방향

## 변경 내용

- 이전에는 `ActorPose.facing`의 좌우 부호로 모델을 두 각도로만 회전시켰다. 이제 Actor의 실제 이동량 `(dx, dy)`에서 `atan2(dx, -dy)`로 glTF +Z 정면의 Y축 회전각을 계산한다. 방향키/WASD의 화면 방향 → 월드 이동 변환과 일치하며 NPC·몬스터에도 공통 적용된다.
- 정지하면 마지막 방향을 유지한다. 충돌로 이동이 막히면 방향을 갱신하지 않으며, 벽을 따라 움직이면 실제 이동 방향을 바라본다. 화면 밖에서 다시 나타나거나 순간이동하면 기존 애니메이션 초기화 규칙을 사용한다.
- `SimpleGame/Config/AssetBindings.json`의 `default_character_scale`을 0.8에서 1.1로 올렸다(기본 높이 약 37.5% 증가). 보스의 명시적 `scale`은 1.5에서 1.9로 올렸다.
- `default_character_thickness: 1.3`으로 로컬 X/Z를 30% 넓힌다. 전체 크기 증가와 함께 기본 캐릭터의 폭·깊이는 이전의 약 1.79배다. 스키닝 후 장비와 몸 전체에 같은 변환을 적용하고, 그 후 회전한다. 발 원점과 높이는 두께 설정의 영향을 받지 않는다. 노멀에도 역전치 스케일을 적용한다.
- 건물·자연물은 두께 1.0을 유지한다. 게임 이동 속도, 충돌 범위, 공격 범위, 저장 데이터는 변경하지 않는다. 원본 Blender/GLB 파일도 수정하지 않는다.

## 성능 및 적용

- 애니메이션 모델은 연속 회전하며 기존 CPU 스키닝과 삼각형 배칭을 유지한다. 추가 연산은 방향 계산과 정점/노멀 두께 변환이다. 메시·삼각형 개수는 증가하지 않으나, 확대에 따른 화면 채움 비용은 실측이 필요하다.
- 애니메이션 없는 모델은 외형당 16개 방향으로 양자화해 회전각마다 무제한으로 메시 캐시가 생기지 않게 한다. 캐시 키에 두께와 새 버전을 포함한다.
- 코드 변경이므로 먼저 다시 빌드해서 실행해야 한다. 이후 JSON의 크기·두께만 변경할 때에는 F10으로 다시 불러올 수 있다. 개별 역할의 `scale`은 기본 크기보다 우선한다.
- 빌드·실행·성능 측정은 사용자 요청 방침에 따라 수행하지 않았다. 사용자가 확인할 항목: 상하좌우 및 대각선 이동 시 정면 방향, 정지 시 방향 유지, NPC/몬스터 이동 방향, 장비 부착과 보행, 보스 크기, 같은 화면에서의 기존 프로파일 로그 비교.
