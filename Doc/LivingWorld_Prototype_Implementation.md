## 바로 플레이하기

빌드 후 실행하면 기존 저장 월드와 같은 시드에서 시작한다. NPC 시뮬레이션 저장 파일이 없으면 주민 24명을 생성한다.
이미 레벨 1 보스를 클리어한 저장이라도 NPC 생활과 일반 몬스터 사냥은 계속된다.

| 입력 | 기능 |
| --- | --- |
| WASD / 방향키 | 이동, 몬스터 자동 조준 |
| NPC 좌클릭 | 동적 NPC를 명시적인 공격 대상으로 선택 |
| 우클릭 | 명시적 공격 대상 해제. 이미 적대적인 NPC는 여전히 자동 방어 대상 |
| T | 마을의 상인 3.5타일 이내에서 재료 판매. 재료가 없으면 회복 구매 |
| Y | 같은 조건에서 금화 20 + 상인 재고 1개로 경험치 20 구매 |
| G | 2타일 이내 NPC 사망 소지품 습득 |
| F / Enter / Space / Esc | 기존 대화 및 거래 결과 창 진행/닫기 |
| P | 일시정지 |
| F9 | 시드·지형·건물·봉화 유지, 플레이와 NPC 사회를 백업 후 초기화 |

좌측 생활 패널은 700×560 이상 창에서 표시된다. 기본 창 크기 1280×800을 권장한다.
선택한 NPC의 직업·행동·목표·HP·레벨·금화·재료·깨달음·핵심 가중치를 볼 수 있다.
좌클릭은 단순 조회가 아니라 공격 선택이므로 중립 주민을 클릭할 때 주의한다.
초록 옷은 사냥꾼, 붉은 옷은 약탈꾼, 금색 옷은 상인, 보라색 옷은 탐구자다.
이안과 세라는 기존 보호 NPC로 공격할 수 없다.

마을 위치:
- 잿빛 마을: (0.5, 0.5)
- 등불 교역소: (26.5, 10.5)

미니맵의 마을 이름/금색 거점과 연결된 길을 따라 이동할 수 있다. 지도 좌표와 화면의 쿼터뷰 방향은 다르다.

## 요청별 반영

### 1. 기존과 비슷한 맵 크기

청크 크기와 화면/줌에 따른 스트리밍 반경은 그대로 유지한다.
월드는 기존처럼 확장 가능하며 새 고정 크기 맵으로 바꾸지 않는다.
프로토타입 사회의 주 활동 범위는 가까운 두 마을과 반경 약 10타일의 사냥터다.

### 2. 마을이 NPC 거점

각 마을에 주민 12명이 소속된다. 건물군·열린 광장·마을 간 연결 길을 생성한다.
NPC는 체력 회복과 거래를 위해 자기 마을로 돌아온다.
마을 반경 4.5타일은 몬스터 접근 제한과 회복 영역이다.
마을은 NPC PK에 대한 완전 무적 구역은 아니다. 마을에서는 PK 선택 가중치를 낮춘다.

### 3. 개별 목표와 직업

각 NPC는 HP/최대 HP, 경험치/레벨, 금화, 재료, 깨달음을 가진다.
성격 6축: 공격성·탐욕·사회성·용기·도덕성·호기심.

- 사냥꾼: 체력과 성장을 우선. 실제 몬스터를 공격하고 재료/금화/경험치를 얻는다.
- 약탈꾼: 부의 축적을 우선. 약한/가치 높은 다른 NPC나 플레이어를 공격하고 소지품을 노린다.
- 상인: 마을 거래를 우선. NPC와 플레이어에게 물품을 사고판다.
- 탐구자: 외곽 탐색을 통해 깨달음과 경험치를 얻는다.

성격은 직업별 기본값에 작은 무작위 차이를 준다.
각 행동은 Hunt / Trade / Loot / PK / Explore / Rest / Flee 중에서 선택한다.
현재 체력·근처 몬스터·금화와 소지품·주변 대상·마을 위험을 반영한 가중치를 만든 뒤 누적 확률로 추첨한다.
공격받거나 행동이 끝났을 때 재평가하며, 일정 간격에도 재평가한다.
사냥·거래·PK 성공과 피해/목격 경험은 learned weight에 반영한다.
실행부는 유한상태 방식의 행동 루틴이다. 범용 Behavior Tree 편집기/노드 프레임워크는 이번에 만들지 않았다.

### 4. PK와 약탈

플레이어는 중립 NPC를 좌클릭으로만 먼저 공격한다. 무작위 중립 NPC는 몬스터 공격에 자동 편입되지 않는다.
선택 NPC → 적대 NPC → 기존 몬스터 순서로 대상을 확인한다.
NPC 대상 플레이어 공격도 기존 원거리 발사체와 지형 충돌을 사용한다.
NPC끼리와 NPC→플레이어 공격은 짧은 공격선으로 표시하는 근접 공격이다.
몬스터도 가까운 전투 중 주민을 대상으로 선택할 수 있다.

주민 피격 시 도주/반격하고 주변 목격자의 성향이 변화한다.
NPC가 죽으면 금화/재료가 바닥 소지품으로 남으며 NPC 또는 플레이어가 실제로 이전받는다.
약탈꾼이 플레이어를 쓰러뜨리면 소지 금화 중 최대 25를 이전받는다. 기존 플레이어 부활·영혼 NPC 생성은 유지한다.
NPC 처치는 플레이어의 몬스터 처치 수로 간주하지 않는다.

### 5. 거래와 성장

NPC 간 재료 거래는 같은 마을에서 3타일 이내일 때 이루어진다. 가격은 재료 1개당 금화 3이다.
플레이어도 같은 가격에 재료를 판매한다.
회복은 금화 10, 상인 재고 1개를 소모해 HP 35를 회복한다.
지식 구매는 금화 20, 상인 재고 1개를 소모해 플레이어 경험치 20을 얻는다.
금화/재고 부족이나 최대 체력·레벨에서는 해당 거래를 거절한다.
거래와 약탈은 양쪽 자산을 증감시킨다. 사냥은 보상 공급원이고 휴식은 생존 수단이다.
NPC 성장마다 최대 체력이 12 증가하며 프로토타입 NPC 레벨 상한은 20이다.

### 6. 실시간 상태 갱신

- 가까운 로딩 지역 NPC: 0.1초 간격 행동/전투/충돌 갱신
- 중거리 로딩 지역 NPC: 0.5초 간격 갱신. 이동은 작은 충돌 검사 단위로 나눈다.
- 미로딩 지역: 15초 간격의 제한된 사냥 자원·깨달음·회복·귀환/거래 요약
- 미로딩 NPC의 실제 Actor는 생성하지 않는다.
- 대화 중에도 세계는 진행한다.
- P 일시정지, 비활성 창, 저장 오류일 때는 멈춘다.
- 프로그램이 종료되어 있는 동안의 오프라인 경과 시간은 계산하지 않는다.

실제 플레이어/몬스터 전투는 로딩된 월드에서만 처리한다.
먼 지역 사냥 자원 풀은 물리 몬스터 개체와 별개의 제한된 요약 자원이며 완전한 개체 단위 LOD 교환은 아니다.

## 몬스터와 인구

각 마을 외곽에 일반 몬스터가 주기적으로 보충된다. 지역 반경 18 내 목표 수는 7이며 전체 실제 몬스터 수는 64로 제한한다.
NPC가 마지막으로 공격해 죽인 몬스터는 해당 NPC가 보상을 받고, 플레이어의 처치/경험치로 중복 지급하지 않는다.
플레이어의 마지막 공격으로 처치하면 기존 파밍 보상에 금화 4와 거래 재료 1이 더해진다.
기존 첫 보스 조건(플레이어 24킬)은 유지한다. NPC도 이미 출현한 보스를 공격/처치할 수 있지만, 문서의 공동 RegionThreat 보스 출현 시스템은 아직 미구현이다.

일반 동적 NPC 목표는 24명이다.
사망한 NPC는 60초 후 그 자리에서 부활하지 않고, 새 ID/성격을 가진 주민이 소속 마을에 유입된다.
사망자의 소지품은 120초 동안 유지하며 사건 기록은 남긴다.
플레이어의 죽음으로 생기는 기존 영혼 NPC는 별도 저장/인구로 유지한다. 영혼의 동적 직업 AI 통합은 후속 작업이다.

## 저장·호환성

기존 월드 시드를 유지한다.
청크 환경 버전은 6이다. 구버전 청크를 읽을 때 해당 월드의 Backups/before_society_v6에 백업하고 마을 배치를 갱신한다.
기존 봉화 위치와 점등 상태, 플레이어 진행 파일과 영혼 데이터는 초기화하지 않는다.
새로 생긴 장애물에 저장 위치가 겹치면 기존 거점 복구가 작동할 수 있다.

world_simulation.dat에 다음을 약 5초마다, 거래/습득 시 및 종료 시 저장한다:
NPC ID/직업/성격/학습 가중치/행동/목표/위치/체력/자산/성장, 사망 대기, 바닥 소지품, 난수 상태, 플레이어 금화/재료.
임시 파일을 작성한 뒤 파일 단위로 교체한다. 잘못된 저장 파일은 자동 덮어쓰지 않고 시뮬레이션을 중단한다.
기존 level_one.dat와 사회 파일은 각각 저장한다. 강제 종료 시 여러 파일을 하나의 거래로 복구하는 통합 트랜잭션 저장은 아직 없다.

F9는 level_one.dat, residents_v1.dat, world_simulation.dat를 함께 백업/초기화한다.
누적 분석 로그는 삭제하지 않는다.

## 분석 자료

기존 렌더링 CSV는 그대로 사용한다.
SaveData/<월드>/에 추가되는 자료:
- world_events.csv: 이벤트 ID, 게임 시간, 종류, 주체, 대상, 수치. 세션 시작은 # 행으로 구분.
- npc_states.csv: 5초마다 NPC별 직업·LOD·행동·HP·성장·자산·깨달음·7개 행동 가중치.
- 콘솔 [Simulation]: 생존 인구/LOD별 인구/총 NPC 금화/이벤트 수.

사건 예: trade, player_sell, player_buy, npc_hunt, npc_level, npc_death, loot, player_loot, player_assault, player_robbed, insight, immigration, lod_hunt.
npc_death의 수치 칸은 사망 원인 CombatKind이며 나머지 사건의 수치는 금화·성장·개수 등 사건별로 해석한다.
로그는 무제한 회전/삭제하지 않으므로 장시간 실행 시 용량 관리가 필요하다.

## 코드 구분

- VillageLayout.h: 마을 위치/이름/영역
- WorldSimulation.h/.cpp: 주민 상태, 가중치 선택, 이동/행동, 생태·인구·LOD
- WorldSimulationCombat.cpp: NPC 전투/보상, 거래/약탈, SceneGraph 등록
- WorldSimulationSave.cpp: 저장/불러오기 및 데이터 검증
- SocietyView.h/.cpp: 주민 외관과 상태 패널
- LevelOneSociety.cpp: 기존 파밍 전투/성장과 연결하는 API
- 기존 LevelOne / GameplayBehaviors: 공통 발사체 경로와 보상 소유자 연결
- 기존 World / WorldView: 마을 생성·청크 갱신·미니맵 표시

NPC/소지품/공격 효과는 기존 Actor/SceneGraph 렌더 경로를 사용한다.
NPC 형상은 직업별 메시 캐시를 공유한다. 신규 로직을 LevelOne.cpp 한 파일에 몰아넣지 않는다.

## 확인할 플레이 시나리오

빌드·실행·테스트는 사용자 요청에 따라 수행하지 않았다. 아래는 검증할 항목이며 통과했다는 뜻이 아니다.

1. 첫 실행: 24명 생성, 마을 이름과 직업별 외관, 상인의 금화/재고 표시.
2. 1~2분 관찰: 사냥꾼의 출발/전투/귀환, 상인 거래, 체력/금화/가중치 변경.
3. 몬스터 사냥 후 T 판매와 Y 성장, 재고/금화 부족 거절.
4. 좌클릭 중립 NPC 공격, 반격/도주/목격 반응, 우클릭 해제.
5. NPC 사망 후 G 습득 또는 NPC 약탈, 60초 뒤 새 주민 ID.
6. 두 번째 마을 이동, 지형 충돌과 길 연결, 근거리/원거리 전환.
7. 종료/재실행: 동일한 NPC 신원·성장·자산 유지.
8. F9: 시드·지형 유지, 플레이와 동적 사회만 초기화.
9. 기존 사망/부활/영혼 NPC, 보스, 메시 캐시, 한글 대화 회귀 확인.

아직 제외한 범위: 전체 퀘스트와 스토리, 500명 대규모 튜닝, 범용 BT, 세력/정교한 범죄·경비·관계망, NPC 장비 슬롯, 영혼 NPC 직업 AI, 완전한 통계/물리 개체 인계, GPU/CPU 실측 최적화.
