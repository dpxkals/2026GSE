# 도로 · 지붕 · 캐릭터 애니메이션 개선

작성: 2026-10-06. 기존 `Fortified_World_RPG_Expansion.md` 이후 변경 기록이다.

## 1. 이중 도로 수정

원인: `World::Generate`가 굽은 지형 도로와 직선 `VillageRoad`를 각각 생성한 뒤
합집합으로 처리했다. 성문 밖에 두 길이 나란히 남는 구조였다.

- 축마다 하나의 중심선을 사용하는 `roadAt`으로 통합했다.
- 원점에서 각 축의 ±126타일까지 성채 연결용 직선을 유지한다.
- 그 바깥 48타일 동안 smoothstep으로 기존 굽은 중심선에 합류한다.
- 타일 생성과 건물 배치 금지 구역이 같은 도로 판정을 사용한다.
- 월드 좌표로 계산하므로 음수 좌표와 청크 경계에서도 동일한 규칙을 사용한다.
- 성벽, 문, 마을 내부 교차로와 기존 마을 개수/위치는 유지한다.

지형 형식은 v8이다. 기존 v2~v7 청크는 로드될 때 `Backups/before_roads_v8`에
원본을 복사하고 갱신한다. 시드, 플레이어 진행 저장, 사회 저장을 초기화하지 않는다.
봉화 및 점등 상태 보존과 성벽 충돌 시 봉화 재배치 규칙도 유지한다.
이미 탐험한 지형의 길과 주변 장애물 배치는 갱신될 수 있다. 변경 내역은 백업 폴더의
`migration.log`와 `[WorldMigration]` 콘솔 로그에 남는다.

## 2. 지붕 형태 수정

원인: 기존 지붕의 위/아래 꼭짓점이 같은 x 좌표에 있어 수직 벽처럼 보였다.

- 네 처마점과 두 용마루 끝점을 가진 박공지붕으로 교체했다.
- 지붕 경사면, 전면 박공, 용마루와 처마 테두리를 구분했다.
- 기와 선은 각 경사면 안에서 보간하고, 먼 면부터 그려 앞면으로 가린다.
- 예배당 지붕 높이를 벽 높이에 맞췄다.
- 구조물 캐시 키를 `prop:rpg3`으로 변경했다. 예전 메시가 덮어쓰지 않으며
  캐시 폴더 수동 삭제나 F9 초기화는 필요 없다.

## 3. 재사용 가능한 2D 부품 리깅

외부 이미지/모델 없이 기존 2.5D 도형 스타일을 확장했다.
`Actor::Animate`가 개체별 포즈를 관리하고 `SceneRenderer::DrawMeshPose`가
캐시된 부품을 관절 기준으로 회전·좌우 반전·착색한다.

| 대상 | 적용 동작 |
| --- | --- |
| 플레이어 / 동적 주민 | 이동 방향 반전, 장화·팔 교차 보행, 망토 흔들림, 호흡, 무기 동작, 피격 반동 |
| 안내 주민 | 호흡, 후드 및 망토의 대기 동작 |
| 동적 주민의 비전투 행동 | 정지 상태의 채집·제작·거래·교류·도움 손동작 |
| 허스크 | 다리/팔 보행, 해골 머리 흔들림, 무기 휘두르기 |
| 하운드 | 네 다리 보행, 몸통의 뜀 움직임, 꼬리, 공격 시 머리 숙임 |
| 보스 | 중갑 보행, 기존 광역 공격 준비 시간에 연동한 자세, 공격 및 피격 동작 |
| 영혼 NPC | 기존 부유 동작 유지, 게임 일시정지에 연동 |

플레이어의 지팡이 결정, 방패 테두리, 활의 화살, 도구의 날을 보강했다.
공격 궤적과 작은 광점은 HDR 발광을 사용한다. 피격에는 색상 변화와 섬광이 적용된다.
플레이어는 몸 전체를 숨기는 기존 무적 깜빡임 대신 피격 반동으로 표현한다.
무적 시간 자체의 게임 규칙은 바꾸지 않았다.

보행은 실제 위치 변화로 감지하며 카메라 이동은 보행으로 처리하지 않는다.
주민의 0.1초 간격 위치 갱신 사이에는 보행 강도를 서서히 줄인다.
공격은 공격 쿨다운이 다시 증가한 시점, 피격은 관측된 체력 감소를 기준으로 한다.
신규 개체/장시간 화면 밖에 있던 개체는 과거 공격을 재생하지 않는다.
별도 애니메이션 시계가 시뮬레이션 진행 중에만 증가하므로 P 정지 시 포즈도 유지한다.
상태는 Actor 수명과 함께 정리되며 저장 형식을 변경하지 않는다.

현재는 연속 변환을 이용한 간단한 2D 관절 애니메이션이다. 8방향 스프라이트,
3D 스키닝, 발 고정 IK, 별도 사망 클립이나 프레임별 판정 변경은 포함하지 않는다.
공격 연출은 기존 즉시 피해/발사 시점을 바꾸지 않는 시각 효과다.

## 4. 캐시와 성능 분석

- 인물: `human:rig2:<style>:<tier>:<part>`, 10종 × 3성장 단계 × 8부품 = 최대 240개.
- 몬스터: `enemy:rig1:<kind>:<enraged>:<part>`, 현재 유효 조합 4종 × 8부품 = 32개.
- 효과: 흰색 궤적과 광점 2개를 캐시하고 인스턴스 색상으로 재사용한다.
- 시간, 개체 ID, 포즈 각도, 화면 위치, 피격 여부는 메시 키에 넣지 않는다.
- 최초 등장 시 생성/파일 저장, 이후 메모리 또는 디스크 캐시를 사용한다.
- 이전 캐시는 삭제하지 않는다. 사용하지 않는 구버전 파일은 디스크에 남는다.
- 캐릭터별 부품 순서를 유지한다. 서로 다른 부품의 짧은 제출 구간은 기존 CPU
  배치로 합쳐지고, 연속된 동일 메시 구간은 기존 인스턴싱 정책을 따른다.
  부품마다 별도의 GL draw를 즉시 호출하지 않는다.

부품 변환과 제출은 프레임마다 수행하므로 CPU 비용이 0인 것은 아니다.
최초 캐시 생성 및 파일 I/O가 발생하는 프레임과, 워밍업 이후 프레임을 나누어 측정해야 한다.
주민 렌더러에도 화면 범위 검사를 적용해 보이지 않는 인물을 제출하지 않는다.

기존 FPS / 실제 glDraw 수 / 업로드 / 캐시 / CPU 로그를 유지하고 다음을 추가했다.

- CSV schema 3: `pose_submissions_last/avg/max` — 포즈 적용 메시 제출 횟수, draw call 수와 다르다.
- 콘솔 `[Profile]`: `posed parts`, `builds` — 프레임당 평균 부품 제출 및 메시 생성 수.
- 로그 context: `terrain=v8;art=rig2;props=rpg3`.

실측 수치는 아직 없다. 고정 카메라에서 같은 외형을 한 차례 표시한 뒤에는 인물/몬스터
부품의 `build` 이벤트가 계속 발생하지 않아야 한다. 새 지형/새 성장 단계/새 몬스터의
최초 표시는 추가 생성이 정상이다. 전체 `generated_vertices`에는 기존 UI·동적 효과도
포함되므로 0 여부만으로 캐릭터 캐시의 성패를 판단하지 않는다.

## 5. 확인 범위 및 사용자 빌드 후 체크리스트

소스 연결, 캐시 키 입력, 변환식, 셰이더의 기존 affine 입력, 저장 버전 처리와
코드 형식을 검토했다. 요청에 따라 빌드·게임 실행·화면 검증은 하지 않았다.

1. 기존 저장으로 실행: v8 백업/갱신 로그, 시드·레벨·NPC 자산 보존 확인.
2. 네 방향 성문에서 외곽 성채까지: 평행한 이중 도로 제거, 청크 경계 통행 확인.
3. ±126~174타일: 직선과 굽은 길의 연결 및 장애물 확인.
4. 주택/예배당: 경사진 지붕, 기와 줄, 굴뚝, 가려짐 반투명 확인.
5. 이동/정지/벽에 막힘: 보행 전환, 방향 반전, 그림자와 관절 이탈 여부 확인.
6. 자동 공격·NPC 사냥/PK·보스 공격: 공격 동작, 궤적, 체력 감소 시 피격 동작 확인.
7. 채집/제작/거래 주민, P 정지/재개, F9 초기화 후 애니메이션 상태 확인.
8. 동일 해상도·줌·인구·후처리 설정에서 워밍업 전후 FPS, draw 수,
   `pose_submissions`, `mesh_builds`, `render_ms`, `upload_bytes` 비교.

성능 감소가 크면 다음 후보는 부품 키 조회 비용 절감, 먼 인물의 간소화,
GPU 관절 변환용 전용 인물 배치다. 이번 변경만으로 FPS 향상을 보장하지 않는다.
