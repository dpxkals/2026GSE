# 로컬 월드 모니터

게임이 만드는 JSON을 받아 NPC와 마을 상태를 보여주는 **읽기 전용 HTML 대시보드**다.
외부 서버·계정·CDN·추가 Python 패키지를 사용하지 않는다.
Sites 스킬의 로컬 전용 흐름에 따라 `dist/`에 빌드 없는 HTML/JS/CSS를 구성했다. 외부 등록/배포는 하지 않는다.

## 실행

1. C++ 프로젝트를 빌드하고 게임을 실행한다.
2. 게임 콘솔의 `[Monitor HTTP] Started:` 주소를 브라우저에서 연다.
   기본 주소는 <http://127.0.0.1:8765>다.
3. 게임을 종료하면 내장 서버와 연결도 종료된다.

Python 설치나 별도 서버 명령은 필요 없다. 브라우저 창은 사용자가 연다.
8765가 사용 중이면 8766~8774에서 빈 포트를 선택한다. 정확한 주소는 콘솔을 확인한다.
게임 프로세스마다 자신의 월드 스냅샷만 전달한다. F9 초기화 후에도 같은 주소를 사용한다.

빌드 시 `Monitor/dist`의 HTML·JS·CSS 3개를 실행 파일 옆 `Monitor` 폴더로 복사한다.
다른 PC로 실행 파일을 옮길 때 이 폴더도 함께 복사한다. HTML 파일을 더블클릭하지 말고
HTTP 주소로 접속한다. 화면 파일이 없거나 포트를 열 수 없으면 콘솔에
`[Monitor HTTP] Disabled:` 오류를 표시하며 게임 및 JSON 파일 기록은 계속된다.

### 기존 Python 서버 (선택 사항)

`serve.py`는 게임이 꺼진 뒤 저장된 JSON을 살펴보는 보조 도구로 남겨 두었다.
게임 실행 중에는 필요하지 않다. 수동 사용 시 Python 3.9 이상에서 다음과 같이 실행한다.

```powershell
py -3 .\Monitor\serve.py --port 8775
```

<http://127.0.0.1:8775>에서 확인하고 Ctrl+C로 종료한다.
이 도구에만 최신 `monitor.json` 자동 탐색과 `--snapshot "전체 파일 경로"` 옵션이 적용된다.

## 확인할 수 있는 상태

- 전역: 생존/존재 NPC, 사망 후 교체 대기 주민, 몬스터 종류별 수, 청크, LOD 인원, 경과 시간.
- 마을: 소속 생존/사망 주민, 현재 체류 NPC, 소속 주민 금화·재료·깨달음 합계,
  평균 체력 비율, 적대/중상 인원, 행동 분포, 주변 몬스터, 지역 자원.
- NPC: 이름/유형, 현재 행동·목표·경험 성향, 체력·레벨·경험치, 금화·재료·깨달음,
  소속/현재 마을, 좌표·목적지·대상, LOD, 성격 6축, 행동 13개의 선택 가중치/학습치.
- 안내 NPC와 영혼 NPC도 표시한다. 없는 체력·경제·AI 수치를 0으로 꾸며 넣지 않고 '해당 없음'으로 구분한다.
- 이름/ID 검색, 유형·마을·상태 필터, 재화/체력/깨달음 정렬, 30명 단위 페이지, NPC 상세 관찰.
- 개체 위치 지도, 최근 사건 5개, 현재 원본 스냅샷 JSON 내려받기.

### 집계 기준

- `summary.npcCount` = 살아 있는 동적 주민 + 안내 주민 + 영혼 NPC. 사망 후 교체 대기 주민은 제외.
- `npcs` 배열에는 사망 주민도 포함하므로 배열 길이와 생존 NPC 수가 다를 수 있다.
- 마을의 `homeAlive/homeDead` 및 자산/체력/행동은 **소속(home)** 기준이다.
- `presentCitizens/residents/souls`는 마을 중심에서 **각 축 11.5타일 미만인 성벽 내부 현재 좌표** 기준이다.
  외출/다른 마을 방문 때문에 소속 인원과 체류 인원은 다를 수 있다.
- 금화/재료/깨달음 합계는 생존 동적 주민만 포함한다. 플레이어와 바닥 전리품은 제외한다.
- 평균 체력은 생존 주민별 `HP / MaxHP`의 평균이며 주민이 없으면 null이다.
- 중상은 HP가 50% 미만인 소속 생존 주민, 적대는 플레이어 적대 타이머가 남은 주민이다.
- 몬스터는 `LevelOne::Enemies()`의 생존 개체만 집계한다. 무한 미생성 월드의 몬스터 수가 아니다.
- 마을 주변 몬스터는 가장 가까운 마을의 30타일 권역에 하나만 배정한다. 겹치는 권역에서 중복 계산하지 않는다.
- 어느 마을 30타일 권역에도 없으면 `outsideMonsters`에 포함한다.
- `resourceStock`은 원거리 사냥/채집용 통계 자원이며 실제 몬스터 수가 아니다.

## 연결과 JSON 메시지

```text
게임 메인 스레드 (1초마다 일관된 스냅샷 직렬화)
  → 내장 C++ HTTP 서버의 최신 스냅샷 (127.0.0.1 전용)
  → /events 의 SSE 메시지 data: JSON
  → HTML / JavaScript EventSource 수신
```

게임 내부에서 직렬화한 JSON을 서버 스레드에 전달한다. 서버는 게임 객체에 접근하지 않는다.
동시에 전용 파일 쓰기 스레드가 실행 파일 옆 SaveData/<월드>/monitor.json을 원자 교체한다.
파일 쓰기 실패가 브라우저 실시간 수신을 막지 않는다. 브라우저가 수신하는 메시지는 JSON이다.
원본 최신 JSON을 한 번 읽으려면 `GET /api/snapshot`을 사용할 수 있다(동일한 메시지 envelope).

SSE 이벤트 이름은 `snapshot`이다. 수신 JSON의 주요 구조:

| 필드 | 의미 |
| --- | --- |
| `type` | `monitor.snapshot` |
| `serverTimeMs` | 중계 서버 시각, Unix milliseconds |
| `source` | 현재 선택한 monitor.json 파일 경로 |
| `state` | waiting / live / paused / blocked / stopped / stale / error |
| `ageSeconds` | 마지막 게임 스냅샷의 경과 시간; 아직 없으면 null |
| `error` | 파일/형식 오류 설명; 정상 시 null |
| `data` | 원본 게임 스냅샷; 아직 없으면 null. 읽기 실패 시 같은 파일의 마지막 정상 스냅샷 |

`data` 계약(`schemaVersion: 1`, `type: world.snapshot`):

- `session`: 실행 프로세스와 시작 시각으로 구분하는 문자열.
- `sequence`: 실행 중 증가하는 스냅샷 번호. `publishedAtMs`: 실제 생성 시각.
- `simulationSeconds`, `seed`, `running`, `paused`, `focused`, `blocked`, `errors`.
- `summary`, `player`, `villages[]`, `npcs[]`, `monsters[]`, `news[]`, `actionNames[]`.
- RPG 확장 필드: `player.level/damage/defense`, `player.inventory`(18종 보유 수량),
  `player.equipped`(무기/방어구/장신구 ID, 미착용 -1).
  `bossEvent`는 마을 인덱스·남은 시뮬레이션 시간·활성 여부,
  `quests`는 보상 수령 플래그(0/1)와 사냥/습득/거래/보스 처치 횟수를 담는다.
  기존 대시보드 레이아웃은 그대로이며 추가 값은 원본 JSON에서 확인할 수 있다.
- `seed`, NPC ID 및 대상 ID는 문자열로 전달하여 JavaScript의 큰 정수 정밀도 손실을 방지한다.
- NPC ID에는 `citizen:`, `resident:`, `soul:` 접두사가 있어 서로 충돌하지 않는다.
- 동적 NPC의 `weights`와 `learned`는 `actionNames`와 같은 순서다. 확률(%)이 아닌 가중치다.
- `personality` 순서: 공격성, 탐욕, 사회성, 용기, 도덕성, 호기심.
- `targetKind`: 0 없음, 1 몬스터, 2 주민, 3 플레이어. `monsters[].kind`: 0 허스크, 1 하운드, 2 보스.
- `lod`: 0 근거리, 1 중거리, 2 원거리. `insideVillage: -1`은 야외다.
- 안내/영혼 NPC의 `alive: true`는 사망 판정이 아니라 해당 개체가 월드에 존재함을 뜻한다.

JSON 문자열은 UTF-8과 제어문자 escape를 사용하며 비유한 실수는 null로 직렬화한다.
임시 파일을 닫은 뒤 Windows 원자적 파일 교체로 부분 JSON 수신을 피한다.
내장 서버는 최신 메모리 스냅샷을 사용한다. 선택적 Python 서버는 파일 수정 시각/크기로 캐시한다.
최대 8 MiB 스냅샷을 지원하며 초과하면 게임 콘솔에 오류를 기록하고 마지막 수신 값은 stale로 바뀐다.

## 백그라운드 진행 / 중단 처리

브라우저에 포커스를 옮겨도 게임 시뮬레이션은 계속 진행한다. 포커스 상실 시 이동 입력은 비운다.
**플레이어도 공격받을 수 있으므로 안전한 관찰이 필요하면 게임에서 P로 일시정지한다.**
일시정지와 게임 오류 중에도 1초 스냅샷은 계속 나와서 '멈춘 게임'과 '끊긴 연결'을 구분한다.
정상 종료 때는 `running: false` 최종 파일을 쓰고 서버와 쓰기 스레드를 정리한다.
종료 직전 stopped 메시지는 브라우저 도착이 보장되지 않으며 서버 종료 후에는 연결 대기를 표시한다.
게임 강제 종료도 서버 연결 종료로 표시한다. 게임이 실행 중인데 새 스냅샷이 5초 넘게
없으면 stale을 표시한다. 브라우저는 자동 재연결을 시도하며 마지막 수치를 유지한다.
P 일시정지 외에도 운영체제 절전/프로세스 정지 중에는 갱신되지 않는다. 게임이 꺼진 동안의 시뮬레이션은 하지 않는다.

## 보안 / 성능 범위

- 서버는 127.0.0.1에만 바인딩하며 다른 PC에 공개하지 않는다.
- 허용된 정적 파일 3개와 index, 읽기 API/SSE만 제공한다. 임의 경로 탐색·게임 상태 변경 API는 없다.
- Host/Origin 검사와 동일 출처 정책을 적용한다. 외부 사이트에서 읽도록 CORS를 열지 않는다.
- 브라우저에서는 JSON 문자열을 HTML로 삽입하지 않고 textContent로 표시한다.
- 디스크 출력은 별도 스레드이고 게임 객체에는 접근하지 않는다. 게임 스레드에는 1초마다 복사/JSON 직렬화 비용이 있다.
- HTTP는 별도 스레드의 비차단 소켓 루프다. 최대 16연결, 요청 헤더 8 KiB,
  요청/송신 제한 시간 5초를 적용하고 느린 연결의 전송 대기열을 누적하지 않는다.
- 성능 수치는 측정하지 않았다. 인구가 크게 늘면 변경분 전송/대상 구독/직렬화 비용 측정이 후속 과제다.

## 수동 확인 목록 (미실행)

요청에 따라 빌드·서버 실행·브라우저 결과 확인은 수행하지 않았다.

1. 새 게임 빌드 실행 후 콘솔 경로에 monitor.json이 1초마다 갱신되는지 확인.
2. Python 없이 게임만 켠 뒤 표시된 주소에서 한국어 NPC 이름과 시드 확인.
3. 주민 이동/전투/거래/사망/교체 후 인원·자산·가중치 변화 및 집계 기준 확인.
4. P 일시정지 중 수신 번호 증가와 시뮬레이션 시간 정지 확인.
5. 브라우저 포커스에서 시뮬레이션이 진행되고 이동 키가 눌린 채로 남지 않는지 확인.
6. 게임 정상/강제 종료 후 연결 대기, 재실행 후 자동 재연결 확인.
7. F9 초기화 뒤 이전 선택 ID와 새 주민 정보가 혼동되지 않는지 확인.
8. 기본 포트를 사용 중일 때 대체 포트 표시와 서로 다른 게임의 데이터 분리 확인.
9. 창 너비를 줄여 표 가로 스크롤·마을 카드·상세 정보를 확인.
10. 읽기 API와 브라우저 JSON 저장 내용을 비교하고, 게임 FPS/디스크 부하를 확인.
