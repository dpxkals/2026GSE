쿼터뷰 월드 렌더링 프로토타입 01
작성일: 2026-09-08

목표
기획서의 첫 기반 단계인 쿼터뷰 렌더링과 청크 스트리밍을 실제 게임 코드로
연결한다. 암울한 숲과 폐허 속에서 봉화에 불을 켜는 작은 상호작용으로,
한번 발생한 변화가 세계에 남는 구조를 보여준다.
화면의 'THE REMAINING LIGHT'는 프로토타입용 문구이며 확정 게임명이 아니다.

이번에 작성한 기능
- 도형 기반 쿼터뷰 타일: 흙길, 풀, 돌, 물.
- 깊이 순서에 따라 그리는 나무, 바위, 폐허, 봉화와 플레이어.
- WASD/방향키 이동, 물과 장애물 충돌, 부드러운 카메라 추적.
- 확대/축소와 창 크기 변경 대응.
- 16 x 16 타일 청크의 점진적 생성, 로딩과 해제.
- 음수 좌표 지원, 주변 청크 지도와 경계 표시.
- 고정 시드 20260908의 지형 생성과 생성 결과의 파일 저장.
- 봉화 점화 및 즉시 저장, 재방문·재실행 시 점화 상태 복원.
- 저장 파일 오류 시 원본을 보존하고 콘솔과 화면에 오류 안내.
- 시작 거점의 NPC 2명: 봉화지기 이안, 떠도는 기록자 세라.
- 한글 이름, 역할, 근접 대화 안내와 여러 페이지의 한글 대화창.
- 재회 여부와 시작 봉화 점화 상태에 따라 달라지는 로컬 대사.
- NPC를 통과하지 않는 충돌과 대화 중 플레이어 이동 정지.
- RGBA16F HDR 장면 버퍼, 밝은 부분의 블룸, 노출과 필름형 톤 매핑.
- 화면 가장자리로 갈수록 강해지는 비네트와 실제 장면 블러.
- 후처리 이후 HUD와 한글 대화창을 별도로 합성하여 가독성 유지.

빌드와 실행
사용자 요청에 따라 이번 작업에서 빌드, 테스트, 실행 및 화면 결과 확인은
진행하지 않았다. 아래는 사용자가 진행할 절차와 확인할 항목이다.

1. SimpleGame.sln을 Visual Studio에서 연다.
2. Debug / x64 구성으로 빌드한다.
   프로젝트는 기존 v143 도구 집합을 유지하며 C++17을 사용하도록 설정했다.
3. Visual Studio에서 실행하거나 x64/Debug/SimpleGame.exe를 실행한다.
4. OpenGL 3.3을 지원하는 실행 환경이 필요하다.
   기존 저장소의 x64/Debug/glew32.dll과 freeglut.dll이 실행 파일 옆에 있어야 한다.
   사용자 지정 출력 경로라면 그 경로에도 해당 아키텍처의 DLL을 배치한다.
5. 이번 렌더러의 셰이더는 코드에 포함되어 작업 폴더에 의존하지 않는다.

조작
WASD / 방향키: 화면 방향에 맞춰 이동. 대각 입력도 지원.
E: 가까운 봉화 점화. 처음 시작하는 위치의 오른쪽 아래에 봉화가 있다.
F: 가까운 NPC와 대화 시작. 시작 위치의 왼쪽에 이안, 오른쪽에 세라가 있다.
대화 중 F / Enter / Space: 다음 대사. 마지막 페이지에서는 대화 종료.
대화 중 Esc: 대화만 닫기. 대화창이 없을 때 Esc는 프로그램 종료.
마우스 휠 / + / -: 확대·축소.
F1: 청크 경계와 청크 좌표 표시 전환.
F2: 전체 후처리 켜기/끄기. 끄면 월드를 기본 렌더링 경로로 직접 출력.
F3: 블룸 켜기/끄기.
F4: 비네트 켜기/끄기.
F5: 화면 가장자리 블러 켜기/끄기.
F6: 후처리 설정을 기본값으로 되돌리기. 월드와 저장 데이터는 유지.
[ / ]: 노출 감소/증가. 0.1 단위, 범위 0.1~4.0.
후처리 조작은 대화창이 열린 동안에도 가능하다.
H: 하단 도움말 표시 전환.
Home: 시작 지점으로 복귀하는 프로토타입용 기능. 세계는 초기화하지 않는다.
Esc / 창 닫기: 종료.

사용자가 확인할 항목
1. 시작 후 지형, 캐릭터, 나무, 폐허, 봉화와 화면 안내가 보이는가?
2. 이동 시 카메라가 따라오고 물·나무·돌·폐허를 통과하지 않는가?
3. 캐릭터가 오브젝트의 앞뒤로 이동할 때 그리기 순서가 자연스러운가?
4. F1을 켠 뒤 경계를 넘어 이동하면 청크 좌표와 활성 청크가 바뀌는가?
5. 음수 좌표 지역에서도 타일이 이어지고 충돌이 동작하는가?
6. 봉화 가까이에서 E를 누르면 불빛과 SAVED 메시지가 나오는가?
7. 충분히 멀리 이동했다가 Home으로 돌아와도 봉화가 켜져 있는가?
8. 프로그램을 종료하고 같은 실행 파일로 다시 실행해도 봉화 상태가 남는가?
9. 창 크기 변경, 확대·축소, 다른 창으로 전환 후 입력이 정상인가?
10. 시작 거점의 NPC에게 접근하면 한글 이름과 F 대화 안내가 보이는가?
11. 대사와 조작 안내에 한글이 표시되고, 창 폭에 따라 줄바꿈되는가?
12. 대화 중 이동하지 않고 Esc로 대화만 닫을 수 있는가?
13. 봉화를 밝힌 뒤 다시 대화하면 봉화에 대한 반응이 달라지는가?
14. 종료 후 재실행하여 대화하면 다시 만났다는 인사를 하는가?
15. E로 봉화를 밝힌 뒤 F3을 전환하면 불꽃 주변의 번짐이 달라지는가?
16. F4를 전환하면 사방 가장자리와 모서리의 어두워짐이 달라지는가?
17. F5를 전환하면 중앙은 선명하고 주변 나무·타일의 윤곽만 점차 흐려지는가?
18. [ / ]로 노출을 바꿔도 UI 글자와 한글 대화창의 밝기·선명도는 유지되는가?
19. F2로 전체 효과를 전환하고 F6으로 초기화했을 때 상단 상태 표시가 바뀌는가?
20. 창 크기 변경과 최소화·복원 후에도 월드가 뒤집히거나 검게 나오지 않는가?

저장 위치
실행 파일이 있는 폴더 / SaveData / World_v1_20260908 /
예: x64/Debug/SaveData/World_v1_20260908/0_0.chunk
청크 전체 타일과 봉화 점화 상태를 저장한다.
같은 폴더의 residents_v1.dat에는 NPC의 고유 ID와 만남 횟수를 저장한다.
NPC는 현재 고정된 시작 거점 인물이며 위치와 인물 정의는 코드로 관리한다.
대사 전체, AI 기억이나 NPC의 이동 이력은 아직 저장하지 않는다.
플레이어 위치는 아직 저장하지 않으며 실행 시 항상 시작 지점에서 시작한다.
Debug와 Release처럼 실행 파일 위치가 달라지면 저장 폴더도 달라진다.
SaveData 폴더는 .gitignore로 Git 관리에서 제외된다.
같은 저장 폴더를 두 프로그램에서 동시에 여는 방식은 지원하지 않는다.

구조
SimpleGame.cpp: 입력, 시간 기반 갱신, 카메라, 쿼터뷰 표현과 HUD.
SceneRenderer.h / .cpp: 삼각형 렌더링, ASCII 글꼴, Windows GDI 기반 한글 텍스트.
PostProcessor.h / .cpp: HDR 프레임버퍼, 밝기 추출, 블러, 비네트와 최종 합성.
World.h / .cpp: 청크, 지형 생성, 충돌과 봉화 상태 저장.
NpcSystem.h / .cpp: 시작 거점 인물, 근접 판정, 로컬 한글 대사와 만남 기록.
Renderer.h / .cpp와 Shaders 폴더: 기존 수업 예제 보존. 새 화면에서는 미사용.

후처리 흐름과 조정 지점
1. SceneRenderer::Begin에서 창 크기의 RGBA16F 프레임버퍼를 선택한다.
2. 월드의 기존 sRGB 색을 선형 색으로 변환하고 발광 배율을 적용해 그린다.
   일반 도형은 Color.energy=1, 봉화 불꽃은 6/8, 플레이어 등불은 3.5이다.
   이 배율은 물리 단위가 아닌 분위기 조정용 상대값이다.
3. 장면에서 밝은 부분을 추출해 가로·세로 절반 해상도로 내리고,
   수평/수직 가우시안 블러 6패스를 적용하여 블룸 이미지를 만든다.
4. 장면 전체의 별도 절반 해상도 이미지에 4패스 블러를 적용한다.
5. 원본과 블러 이미지를 중앙에서 가장자리로 강해지는 마스크로 혼합한다.
6. 블룸을 더하고 비네트, 노출, ACES 계열 근사 곡선의 톤 매핑을 적용한다.
   이는 완전한 ACES 색 관리 시스템은 아니다.
7. 최종 색을 sRGB로 한 번 인코딩하여 기본 화면 버퍼에 출력한다.
8. SceneRenderer::FinishWorld 이후 한글 이름, 대화, HUD를 선명하게 그린다.

설정 기본값은 PostProcessor.h의 PostProcessSettings에서 변경할 수 있다.
전체 효과/블룸/비네트/가장자리 블러: 모두 켜짐.
exposure=1.1, bloomStrength=0.35, bloomThreshold=1.0,
vignetteStrength=0.48, edgeBlurStrength=0.85.
가장자리 마스크의 범위는 PostProcessor.cpp의 CompositeFragment에 정의된다.
후처리 설정은 현재 실행 중에만 유지되며 다음 실행에는 기본값으로 돌아온다.

셰이더 또는 HDR 버퍼 초기화 실패 시 콘솔에 원인을 출력하고 기본 렌더링으로
돌아간다. 상단에는 POST UNAVAILABLE이 표시된다. 버퍼 크기 관련 실패는
동일한 크기에서 매 프레임 재시도하지 않고, 창 크기가 바뀌었을 때 다시 시도한다.

현재 범위와 한계
- HDR은 내부 렌더링 계산 방식이다. 출력은 SDR/sRGB이며 HDR10 출력,
  Windows HDR 모드나 HDR 모니터를 요구하지 않는다.
- 노출은 수동이며 자동 노출, 깊이 기반 피사계 심도, PBR 조명은 아직 없다.
  가장자리 블러는 깊이값이 아닌 화면상의 위치로 강도를 정한다.
- 기존 타원형 광원 연출은 남아 있지만 좌우 사각형 어둠 오버레이는 제거했다.
  새 비네트와 블러는 완성된 월드 렌더링 이미지를 입력으로 사용한다.
- HDR 버퍼 1개와 절반 해상도 중간 버퍼 4개를 사용한다. 창이 커질수록
  GPU 메모리와 처리 비용이 증가한다. 블룸/블러를 끄면 해당 필터 패스는 생략한다.
- 청크 경계 디버그 선은 월드 패스에 포함되어 후처리의 영향을 받는다.
- 최종 아트가 아닌 도형 기반 그래픽이다. 기존 상태 UI는 ASCII 글꼴,
  NPC 이름과 대화는 Windows의 맑은 고딕(Malgun Gothic)을 사용한다.
  한글 텍스트는 GDI에서 그린 뒤 OpenGL 텍스처로 캐시하며 별도 폰트 다운로드는 없다.
  한글 글꼴을 사용할 수 없는 환경에서는 한글 표시가 제한될 수 있다.
  한글 리터럴을 포함한 소스는 /utf-8 및 개별 PCH 미사용 설정을 적용한다.
- 저장 작업과 생성 작업은 갱신당 최대 3개 청크의 동기 방식이다.
  큰 지형이나 느린 디스크를 위한 작업 스레드 기반 비동기 스트리밍은 후속 단계다.
- 지형이 준비되기 전에는 어두운 배경이 보일 수 있고 미로딩 지역 이동을 막는다.
- 청크 좌표는 64비트 정수지만 플레이어 위치는 double이다.
  현실적으로 무한한 정밀도를 보장하지 않으며 극단적 거리의 정수·지역 좌표 분리는 후속 과제다.
- 봉화 주변 네 칸은 비우지만 모든 생성 봉화까지의 경로 연결성을 보장하는
  지역 단위 검증은 아직 없다. 시작 봉화는 비어 있는 시작 거점에 배치한다.
- 2D 바닥 기준 깊이 정렬이므로 복잡한 다층 건축물과 교차 구조는 후속 과제다.
- 생성 파일은 버전 1이다. 기존 파일을 유지하므로 생성 코드를 바꿔도
  이미 저장된 청크는 바뀌지 않는다. 마이그레이션은 아직 구현하지 않았다.
- 파일 교체 기반 저장을 사용하지만 백업, 체크섬, 자동 복구는 후속 과제다.
- 이번 NPC는 대화 기능용 고정 인물이며 사망으로 태어난 존재가 아니다.
  대사는 조건에 따라 선택하는 로컬 스크립트이고, AI가 생성하는 대사가 아니다.
  사망과 생명 전송, AI 대화, 전투, 인벤토리, 퀘스트는 아직 구현하지 않았다.
- 봉화 상호작용은 기획서의 영속성과 희망을 작게 검증하기 위한 제안 구현이다.

다음 단계 후보
화면과 이동 피드백 반영 → 비동기 청크 스트리밍 → 저장/복구 강화
→ 행동 기록과 사망 시 NPC 생성 → NPC의 특성과 기억을 반영한 대화.
